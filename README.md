# Class Adviser's Portal

## Start the portal

The portal uses its Node.js backend and local SQLite database. Do not use VS Code Live Preview to run the application.

1. Double-click `start-portal.bat`. On the first run it checks Node.js and installs dependencies from `package-lock.json` when needed. Alternatively, open a terminal in this folder, run `npm ci`, then run `npm start`.
2. Keep the terminal window open while using the portal.
3. Open the exact `http://127.0.0.1:...` address printed in the terminal. The default port is `3003`; if it is occupied, the server tries the following ports and prints the one it selected.

If you already had the portal running when code was updated, stop that old Node server and start it again. A running Node process keeps its old API routes in memory even though it may serve an updated `index.html` from disk. The import button posts to `POST /api/students/import` on the same origin as the portal page; do not change the port manually or open the page using Live Preview.

On a new computer, install Node.js 22.5 or newer and start the portal with `start-portal.bat`, or run `npm ci` followed by `npm start` from this folder. The Node.js built-in `node:sqlite` module is used; no separate SQLite server or Express installation is needed.

### If the browser cannot connect

- Start the app with `start-portal.bat` or `npm start` from the folder containing `server.js`; keep that terminal open.
- Open the exact `http://127.0.0.1:...` URL printed by the server. The default port is `3003`; if occupied, the server tries ports through `3023`. Do not assume the address is still `3003`.
- Visit that same address followed by `/api/health`. A healthy backend returns `{"status":"ok","storage":"sqlite"}`. If the browser shows the frontend but its API requests fail, check that the address is from this Node server, not a directly opened `index.html`, VS Code Live Preview, GitHub repository page, or GitHub Pages.
- On first start, the server creates the SQLite database and migrates `grade5-portal-database.xlsx` if present, otherwise `grade5-portal-database-template.xlsx`. A new clone therefore starts with an empty database. Existing account, learner, grade, and attendance data is not included in the GitHub repository.
- If `/api/health` returns an error, check the server terminal for the database path and migration error. Confirm the template workbook is present and readable, and that the folder is writable. Set `PORTAL_DATABASE_PATH` to a writable database path or `PORTAL_MIGRATION_WORKBOOK` to a readable workbook if using custom locations.
- The portal binds to `127.0.0.1` by default for local use. For a hosting service that assigns a port, set its `PORT` environment variable and bind publicly with `HOST=0.0.0.0`; configure persistent storage for the SQLite file. GitHub Pages cannot run this Node.js backend.

## SQLite backend

The portal stores live data in `grade5-portal-database.sqlite` in this application folder; Excel is not used as the live backend. On the first start, the server migrates the existing `grade5-portal-database.xlsx` into SQLite and leaves the original workbook unchanged as a backup. If the application workbook is missing, it checks the Downloads database and then the legacy template. The server prints the SQLite path at startup. To select a different SQLite database, set `PORTAL_DATABASE_PATH`; set `PORTAL_MIGRATION_WORKBOOK` to specify a different source workbook for a new, empty database.

The server reads and writes the SQLite database; the browser never accesses it directly. After migration, the source workbook is only needed as a backup. SF1/SF2 import and SF2 export continue to use Excel files.

The SQLite database contains the migrated portal records, including accounts, roster, grades, attendance, and sign-in history. Passwords remain PBKDF2 hashes. The database is created on the first request after startup; keep it with the app and include it in regular backups. No demo accounts, students, or grades are added during migration.

Teachers enter their classroom number when signing up. The portal creates the class and a unique parent join code, then displays that code after registration and on future teacher sign-ins. Parents can sign up with a join code from their teacher. A class must exist before a parent can register. After a parent registers, teachers can select **Refresh roster** on the student list to reload available parent accounts before linking them to learners.

The teacher navigation includes **Settings** after **Teacher Profile**. Under **Appearance**, choose **Use device setting**, **Light**, **Dark**, or one of 20 additional color themes. The preference is saved in the current browser.

After registration or sign-in, parent accounts open the **Parent Portal**, which displays class and adviser information plus the profile, saved attendance, term grades, and BOSY/MOSY/EOSY reading results for learners explicitly linked to that parent account. Reading results include the history of numbered attempts and their automatically recorded dates. The parent Reading Progress area has a period comparison graph with English and Filipino assessment dates, plus a separate chronological graph plotting every dated attempt over actual dates. Reading Progress refreshes when opened and also has a manual refresh button so newly saved teacher assessments appear without signing in again. A collapsible **Sections** hamburger menu appears in the left sidebar directly above **Sign out**, outside the learner information cards, and navigates to Student's Information, Attendance, Reading Progress, and Term Grades. On narrow screens, the sidebar can be opened from the top-bar menu. Parent term grades display Terms 1–3 side by side, with an **Average** column averaging all three terms for each subject. The bottom-right **General Average** cell averages the eight core subjects (including MAPEH, but excluding Music and Arts and Physical Education and Health as separate subjects) across all three terms. It appears only when all core grades for all terms are available; no term-specific General Average values are shown in the footer. Parents cannot browse the class roster or access another learner's records. From **List of Students**, teachers can choose a registered parent from the **Parent account** dropdown for each learner, or choose **Not linked** to remove the link. The dropdown only includes active parent accounts registered with that teacher's class.

## Importing an SF1 roster

Teachers can select **Import SF1** from the student roster and upload the SF1 Excel register in `.xls` or `.xlsx` format. The filename and extension do not matter; the portal identifies supported Excel workbooks from their file contents, then checks for the SF1 register headings. It reads student rows with a 12-digit LRN, name in `Last Name, First Name, Middle Name` order, sex, and birth date. It also imports mother tongue, ethnic group, religion, address, father's name, mother's maiden name, and guardian relationship when present. Only these student roster fields are imported; school details, totals, legends, and other workbook content are ignored. The uploaded file is processed locally by the portal and is not saved as an upload. The API returns a clear error for an unsupported or unreadable workbook rather than a generic route error.

Imported students are saved to the signed-in teacher's class in the `Students` worksheet. LRNs already in that class roster (or repeated in the file) are skipped. Rows with missing or invalid required information are skipped and listed in the import result; other valid rows are still imported. Import accepts files up to 10 MB and up to 1,000 student rows.

The **List of Students** page includes **Clear List** for teachers who need to empty their class roster. The teacher must enter the current account password and then confirm deletion. This permanently removes that class's students and their grades, attendance, and reading assessments; parent accounts and class settings are retained.

## Term grades

Teachers can open **Term Grade** from the hamburger navigation, choose one of the three terms (Term 1, Term 2, or Term 3) and a student, then enter subject grades from 0 to 100. **Save Grades** stores and locks grades for the selected student and term. Select **Edit Grades** to make that student's grades editable again; saving the changes locks them again. Each student's lock is independent, stored in the `Term Grade Locks` worksheet, remains available after a server restart, and is enforced when grades are saved. Legacy term-wide locks are cleared rather than applied to all students because they do not identify a specific learner. Entered grades are stored in the `Term Grades` worksheet. MAPEH is calculated as the average of the Music and Arts and Physical Education and Health grades; both component grades must be entered for the average to appear. General Average is the average of Filipino, English, Mathematics, Science, Araling Panlipunan, GMRC/Values Education, EPP/TLE, and MAPEH. It appears once all eight grades are available and does not count Music and Arts or Physical Education and Health separately. Parents cannot view or change teacher grade records.

## Attendance

Use the date-level dropdown in the attendance table to mark a date **Holiday/No Class**. This clears and locks attendance for that date across the class, displays **NC** for every learner with a light-gray background, and excludes the date from the month's class-day total. The setting persists when the month is reloaded and can be reversed by selecting **Class Day**. SF2 imports do not add attendance records on dates marked **Holiday/No Class**; imported `NC` marks are recognized as no-class dates.

Monthly learner statuses include a required effective date within the selected month. An **NLS** or **Transferred Out** status locks that learner's attendance beginning the next month and in all later months until the status changes to **Transferred In**. The learner remains visible in the roster and is excluded from attendance totals while locked. A **Transferred In** date excludes the learner's attendance before that date in the selected month. SF2 exports preserve the status date in the Remarks cell and show `N/A` for locked learner-days; importing the generated SF2 preserves the effective date and does not add attendance for those days.

SF2 **Average Daily Attendance** and daily gender/combined attendance totals are calculated from learners registered at the end of the selected month. NLS and Transferred Out learners are excluded from those totals, and locked `N/A` days are not counted as present.

Teachers can open **Attendance** immediately after **List of Students** in the hamburger navigation. Choose a month and year to display the DepEd School Form 2 (SF2)-style daily attendance sheet with the complete roster grouped by gender, Monday-to-Friday dates and weekdays across the page, monthly Present/Absent/Tardy counts, and per-student remarks. Saturday and Sunday are omitted from the attendance sheet. Choose Present, Absent, Tardy, or Excused for each weekday; a reason is required for every date marked Absent. Male, female, and combined total rows tally Present, Absent, and Tardy by weekday and for the month. Save the register to the workbook's `Attendance Records` and `Attendance Monthly Notes` worksheets; saved entries can be updated or cleared from the sheet. **Import SF2** accepts an `.xlsx` SF2 workbook with a worksheet named for the selected month (for example, `OCT 2026`) and the project template's layout. Learner names must uniquely match the teacher's roster and appear in the matching gender section. Import replaces attendance and remarks only for matching learners in the selected month; other months and roster learners omitted from the file are unchanged. Blank marks on dated weekdays mean Present; `x` means Absent, `h` Half-day, `t` Tardy, and `e` Excused. For an Absent mark, enter a reason in that learner's SF2 remarks cell; that remark is also saved as the monthly remark. Unsupported marks, unmatched names, and absent marks without a reason are rejected without changing attendance. **Download SF2** creates a separate workbook from the project's `SF2.xlsx` template for the selected month, includes the current class roster and saved attendance, clears the template's example learner rows, and hides unused learner rows so the visible roster expands or contracts to match the actual student count. It synchronizes the bottom-right gender and total enrollment, average daily attendance, and attendance percentage summaries to the current roster and attendance. Summary formulas are refreshed with matching cached values and recalculation is enabled when opened in Excel. The exported worksheet's **Displayed Month** in `AA6` and month summary in `AG117` are synchronized to the selected month, along with its date and weekday headings; attendance marks align with those dates. Its **No. of Days of Classes** total (including `AJ117`) reflects the month's weekdays, minus dates marked **Holiday/No Class**. The exported file is named `SF2_(Month)_(Year).xlsx` (for example, `SF2_January_2026.xlsx`). When date-specific absence reasons differ from monthly remarks, the export includes a date-qualified **Grade Portal absence reasons** block in the remarks cell so those reasons survive a later import. The template supports up to 50 learners in each gender section (100 total). Parents see attendance dates, statuses, and absence reasons only for learners linked to their account in the Parent Portal; use **Refresh** in the attendance section to load the latest records while the portal is open.

## Reading progress

Teachers can open **Reading Progress** from the hamburger navigation. Its controls are grouped into **Reading Reports** and **Record Assessments** for easier navigation. Each period's report shows English and Filipino reading-level charts, assessment coverage, and a learner-by-learner view for that period. Use **Record BOSY**, **Record MOSY**, or **Record EOSY**, then choose an assessment attempt number (1 for the first assessment, 2 for the second, and so on) to save levels independently for that period and attempt. Saving the same period and attempt updates that attempt; other attempts remain in the history. Assessment dates are recorded automatically when saved. The available levels are Non-reader, Frustration, Instructional, and Independent; use the categories specified by your school's assessment rubric. Leave a language as Not assessed when no result is available. Results are saved in the workbook's `Reading Assessments` worksheet and are scoped to the teacher's class. Parents can view the complete dated reading assessment history only for learners linked to their account.

The Attendance page also has a **Summary Of Attendance** tab. It lists every learner currently in the roster and totals saved attendance records across months, from the earliest through the latest recorded date. Present and Tardy each add one to Present; Half-day adds 0.5; Absent adds one to Absent. Excused and unmarked days, Holiday/No Class dates, and days locked by NLS/Transferred Out status are not counted. Use **Refresh** to reload the totals.

## Teacher profile

Teachers can open **Teacher Profile** from the hamburger navigation to update the name and email used by their account, classroom number, grade, section, school year, Name of School, School ID, and School Head. Name of School and School ID appear in the corresponding header fields of generated SF2 files. Email changes apply to future sign-ins, and classroom numbers must remain unique. Class and school details are saved with the teacher's class. Teachers can change their password after verifying the current password and can upload or remove a JPEG, PNG, or WebP profile picture up to 2 MB. Pictures are stored in a `*.profiles` folder beside the configured database and are served only to the signed-in teacher.

The Node test suite uses temporary SQLite databases and workbook migration copies; it does not change the live database. Run it with `npm test`.
